BUILD & RUN
--------------------------------------------------------------------------------
Configure (first time or after CMakeLists changes):
  cmake --preset debug

Build everything:
  cmake --build --preset build-debug

Build a specific target:
  cmake --build --preset build-debug --target SpinDemo
  cmake --build --preset build-debug --target ClearDemo

Run SpinDemo (spinning cube demo):
  build\debug\src\demos\Debug\SpinDemo.exe [optional-path-to.glb]

Run ClearDemo (minimal green-screen sanity test):
  build\debug\src\demos\Debug\ClearDemo.exe

Run unit tests:
  cd build\debug && ctest -L unit --output-on-failure

Run integration tests (requires physical GPU + display):
  cd build\debug && ctest -L integration --output-on-failure

TECH STACK
--------------------------------------------------------------------------------
- C++20, MSVC v143, CMake 3.26+ with presets, vcpkg manifest mode
- DirectX 12 (sole backend); DXC (directx-dxc via vcpkg) for HLSL → .cso
- Custom math library: RH, Y-up, row-major Mat4
  - Row-vector convention: v' = v * M in C++, mul(v, M) in HLSL
  - lookAtRh: camera +Z points BACKWARD (eye - target); objects in front
    have NEGATIVE view-space z. perspectiveRhYupReverseZ expects this.
  - HLSL cbuffer matrices MUST use `row_major float4x4` — without it HLSL
    transposes the data and transforms are completely wrong.
- Reverse-Z depth: near=1, far=0; DepthFunc=GREATER_EQUAL; clear to 0.0f
- Winsock2 UDP + custom reliability layer (networking)
- Archetype-based ECS
- Third-party (approved): DirectXMath, DXC, WinPixEventRuntime, stb_image,
  meshoptimizer, cgltf, Dear ImGui (docking branch), GTest 1.14+, GBenchmark

KEY FPS DESIGN DECISIONS (from Phase 6 docs)
--------------------------------------------------------------------------------
- Server-authoritative, 64 Hz fixed tick. Clients predict locally, reconcile.
- WorldState snapshots sent ~20 Hz (every 3 ticks); delta-compressed per entity.
- Client-side prediction: local CharacterController applies input immediately;
  server correction triggers rollback+replay if divergence > 5 cm.
- Remote entity interpolation: 100 ms behind, 3-snapshot buffer, SLERP rotation.
- Lag compensation: server rewinds entity positions to shooter's timestamp for
  hitscan hit validation; bounded by client RTT anti-cheat check.
- Physics: server-only authoritative simulation; dynamic RB state replicated
  every snapshot; static geometry never replicated.
- .scene format: TOML header + packed binary SoA component data + asset table.
- Editor: EngineEditor.exe, ImGui docking, GPU object-ID picking, Play-in-Editor
  (in-process local server+client), ImGuizmo gizmos, 100-command undo stack.
- Save system: player .profile, per-match .matchrecord, server .checkpoint files;
  LZ4-compressed, CRC32-verified, forward-compatible with unknown-field skipping.

--------------------------------------------------------------------------------
KNOWN API DEVIATIONS FROM DESIGN DOCS
--------------------------------------------------------------------------------
1. MeshManager must be constructed AFTER beginFrame() — it captures the open
   command list at construction time. Upload pattern:
     device.beginFrame();
     MeshManager meshMgr(device);
     MeshHandle h = meshMgr.uploadStatic(verts, indices);
     device.endFrame();   // submits copy commands
     device.flush();      // waits for GPU

2. Quat::fromAxisAngle is a FREE FUNCTION, not a method.
   Use: engine::core::math::fromAxisAngle(axis, angle)

3. Mat4 has no .data() method — use &mvp.m[0][0] to get float* pointer.

4. FlatShadePass API requires width+height explicitly (not derived from FB).

5. addFlatShadePass requires MeshHandle (not raw buffer handles).

6. SpinDemo uses integer DXGI_FORMAT values (87 = R8G8B8A8_UNORM,
   20 = D32_FLOAT) to avoid exposing DX12 headers in the demo.

7. lookAtRh is STANDARD RH (camera +Z backward, objects in front at -z_view),
   NOT the "+Z forward" convention the original design comment implied.
   cameraViewMatrix passes forward = rotate(q, {0,0,-1}) as target offset.

8. All HLSL cbuffer matrices must be declared `row_major float4x4`.
   Without this, HLSL transposes the data → wrong vertex transforms.

--------------------------------------------------------------------------------
CRITICAL BUG HISTORY (fixed, but important for future work)
--------------------------------------------------------------------------------
BUG A — Double barrier crash:
  FrameGraph post-execute loop AND endFrame() both emitted RT→PRESENT barrier.
  Fix: added `if (vr.isBackBuffer) continue;` in FrameGraph post-execute loop.

BUG B — MeshManager on closed command list:
  MeshManager captures the command list at construction. Constructing it before
  any beginFrame() captured a closed list → upload commands never submitted →
  GPU buffers uninitialized → no geometry. See API deviation #1 above.

BUG C — lookAtRh wrong zAxis sign:
  `zAxis = normalize(target - eye)` gave positive z_view for in-front objects.
  Projection has w = -z_view → negative w → hardware clips everything silently.
  Fix: `zAxis = normalize(eye - target)` in Mat.cpp.

BUG D — HLSL missing row_major:
  `float4x4 gMVP` without `row_major` makes HLSL read the data transposed.
  Translation lands in wrong axis; transforms are completely wrong.
  Fix: `row_major float4x4 gMVP` in FlatShadeVS.hlsl.
